# supatype/homebrew-tap

Homebrew tap for the [Supatype](https://supatype.com) CLI.

```bash
brew tap supatype/tap
brew install supatype
```

Homebrew maps `supatype/tap` to this repository, `supatype/homebrew-tap`, so the tap name has
no `homebrew-` prefix even though the repository does.

> **Status:** the first formula is published with the first standalone CLI release. Until then,
> install with `npm install -g @supatype/cli`.

## What is in here

| Path | Purpose |
|------|---------|
| `Formula/supatype.rb` | Generated by the release pipeline. Do not edit by hand, it is overwritten on every release. |

## How the formula is updated

Releases are cut in the [supatype monorepo](https://github.com/supatype/supatype). A `v*` tag
compiles the CLI for every platform, publishes the archives to `releases.supatype.com`, then
regenerates `Formula/supatype.rb` from the archives that were actually published and commits it
here.

The formula is therefore a product of a release, never an input to one. If a formula looks
wrong, fix the generator in the monorepo
(`packages/cli/scripts/generate-homebrew-formula.mjs`) rather than editing the `.rb`, because
the next release will overwrite anything committed by hand.

## Verifying a download

Each release publishes `checksums.sha256` alongside the archives, signed with
[minisign](https://jedisct1.github.io/minisign/). The formula pins the SHA256 of the archive it
installs, so Homebrew refuses a download that does not match. `supatype self-update` verifies
the signature as well as the checksum; note that Homebrew installs are updated with
`brew upgrade supatype` rather than `self-update`.

## Reporting problems

Formula problems and CLI problems both belong in the
[monorepo issue tracker](https://github.com/supatype/supatype/issues). This repository holds
generated output only, so an issue opened here would have to be moved before it could be fixed.
